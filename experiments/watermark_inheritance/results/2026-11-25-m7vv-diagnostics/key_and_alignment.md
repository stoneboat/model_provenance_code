# Key, token, and alignment checks

With key 101, 80.35%, 80.29%, and 80.52% of eligible **emitted tokens** in the 1,600 evaluation triples were green on S, S′, and S″. With the pre-existing wrong key 900101 those rates were 25.15%, 25.15%, and 25.05%. This verifies that the original generator placed a strong, common watermark on all three realized shards. These values measure the token that was sampled by the watermarked generator. The primary audit measures a different event, whether the evaluated target's unconstrained argmax for that context is green. [Held-out and construction summaries](emitted_watermark.csv)

The actual settings were two-token context, hash salt 35317, key 101, 12,569 green tokens out of 50,277 valid tokenizer IDs, and 27 excluded model-padding IDs. Generation masked the padded vocabulary, then added bias 3 in float32 before sampling at temperature 0.8 and top-p 0.95. All final tokenizers had the same complete token-to-ID mapping as the generator. Input preparation retained all stored completion tokens, masked prompt and padding labels, and used a one-token causal shift. All 6,000 stored prompt/completion sequences fit the training context cap. The original reading code gathered top-1 predictions from the unbiased model at indices beginning at prompt length minus one, excluded previously seen two-token contexts, and used the same key and valid vocabulary. An independent CPU reimplementation of the upstream salted hash and permuted greenlist reproduced all 12,000 stored green counts, eligible counts, and z-scores for the three targets on S/S′ (absolute z disagreement below 1e-12). An additional index check directly fed each prefix ending immediately before the queried token to the CPU BF16 model. On 32 positions from the first four construction pairs in A, the cached GPU winner equalled the CPU winner at 25 positions and tied for first at three more. The remaining four discrepancies were one BF16 grid step (4 logits) below the CPU maximum; this cross-device spot check is not bit-exact. [Per-prefix results](prefix_checks.json)

A separate CPU precision comparison used all 7,989 completion positions on the first 16 construction pairs, with queries fixed across dtypes and models. The pretrained base already had a large common logit component. Its median BF16 peak was 836 with representable spacing 4, and 71.42% of rows had multiple top-ranked tokens, compared with zero top ties in FP32. Corresponding values for final A were median peak 832, spacing 4, BF16 tie rate 69.56%, and FP32 tie rate 0.013%. BF16 and FP32 top-1 tokens agreed on 47.65% of base positions and 46.83% of A positions. Casting the stored rounded logits to float32 in the scorer cannot recover their original ordering. This demonstrates a numerical limitation in the argmax channel. It does not on its own demonstrate that a higher-precision readout separates the shards.
