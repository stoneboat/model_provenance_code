# GPT-Neo-1.3B after matched Lamini Docs fine-tuning

**Yes.** The public audit detected GPT-Neo-1.3B after fine-tuning on exactly the Lamini Docs examples used for the Pythia derivative. Its MIN-K20 advantage went from +0.305 to +0.275, and mean log-probability advantage went from +0.355 to +0.330. Both signals were present before adaptation and persisted afterward.

Every observed advantage is positive, so its absolute value equals the magnitude shown. All eight observed values exceed the 0.1358 individual reference. For GPT-Neo-Lamini, both also clear the 0.1480 two-score reference. MIN-K20 accepted 95 member-source and 40 nonmember-source examples. Mean log probability accepted 103 and 37, respectively, out of 200 per source.

**Downstream adaptation.** On the same 140 held-out Lamini examples (8,576 answer/EOS tokens), GPT-Neo answer NLL fell from 2.0524 to 1.5002, a 26.9% reduction. The paired 95% bootstrap interval for the change was [−0.607, −0.504] nats per token. On the 124 held-out rows whose normalized question and answer were both unseen in training, NLL fell from 1.9934 to 1.4918. Full-training-set NLL fell from 2.1818 to 1.5089. The 237 training updates took 226 seconds on one A100-SXM4-40GB. A zero-update merge and reload reproduced both cached scores on all four smoke-check construction examples. ### Rebuttal paragraph for qmGv.Q1(b)

Yes. We fine-tuned independently pretrained GPT-Neo-1.3B on the same 1,260 Lamini Docs examples, in the same order and with the same three-epoch LoRA protocol as our Pythia derivative. On the frozen MIMIR GitHub evaluation shards, GPT-Neo-Lamini yielded advantages of 0.275 (MIN-K20) and 0.330 (mean log probability), compared with 0.330 and 0.375 for Pythia-Lamini. Both GPT-Neo-Lamini scores exceeded the two-score family-wise reference cutoff of 0.148, while shuffled-label advantages were −0.035 and 0.000. GPT-Neo already exhibited a positive signal before fine-tuning. The signal therefore persists after matched downstream adaptation in a separately pretrained Pile model, showing that a positive public audit on these shards cannot uniquely establish Pythia ancestry.

## Verification

GPT-Neo-1.3B and Pythia-1.4B are separately pretrained model families. Both name the Pile as their training corpus. This comparison matches downstream examples exactly. Pretraining example order and individual witness exposure across families are unknown. [GPT-Neo model card](https://huggingface.co/EleutherAI/gpt-neo-1.3B) · [Pythia model card](https://huggingface.co/EleutherAI/pythia-1.4b/blob/fedc38a16eea3bd36a96b906d78d11d2ce18ed79/README.md)

- **Base and tokenizer.** GPT-Neo and its native GPT2TokenizerFast use commit `dbe59a7f4a88d01d1ba9798d78dbe3fe038792c8`, matching the pretrained audit. The Pythia base and tokenizer used in the two comparator arms are pinned at `fedc38a16eea3bd36a96b906d78d11d2ce18ed79`. The tuned Pythia comparator is our matched LoRA run.
- **Downstream exposure.** Both adapters use the same Lamini Docs train parquet at `05bd680b81d69a7a1d38193873f1487d73e535bf`, with all 1,260 rows once per epoch for three epochs. GPT-Neo consumed 78,293 supervised answer/EOS tokens per epoch. Its longest sequence was 473 tokens, within the 512-token limit. The prior overlap screen recorded zero normalized contiguous 13-word matches between Lamini training questions/answers and the MIMIR shards. Shorter or paraphrased overlap remains possible. [Dataset preflight](../../../../artifacts/lamini_matched/preflight.json) · [Overlap screen](../../../../artifacts/lamini_design/overlap.json)
- **Training.** The smoke test updated all 48 intended adapter projections using four actual training rows. The full run started afresh from the base. It reused the saved Pythia row permutations, rank 16, alpha 32, adapter dropout 0.05, frozen BF16 backbone, FP32 adapters, and answer/EOS-only supervision. The architecture-specific targets were attention output and MLP down projections in each of 24 layers (5,505,024 trainable parameters). AdamW used peak LR 0.0002, betas (0.9, 0.999), epsilon 1e-8, zero weight decay, and gradient clipping at 1. Microbatch size was four with four accumulation steps, including the last partial group. The fixed schedule used 12 warm-up updates then linear decay through update 237. [Exact configuration](protocol.yaml) · [Smoke test](smoke.json)
- **Witness evaluation.** The frozen MIMIR GitHub seed-0 split provides 500 construction and 200 held-out snippets per source. IDs, text hashes, source labels, and row order matched each of the three cached comparator score files on both splits. We fitted each model and score independently using the first of 2,001 ascending thresholds maximizing construction balanced accuracy. A score at or above that threshold predicts the member source. The reported advantage is the held-out member acceptance rate minus the nonmember acceptance rate. Shuffled controls preserve class counts, shuffle construction then evaluation labels using seed 42, and refit the threshold. The per-score reference is 0.135810. For the two scores of the new model the Bonferroni reference is 0.148021 at nominal family level 0.05. These are reference cutoffs for the train-versus-validation witness.
